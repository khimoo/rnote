# PDF のセクションに沿ってページを並べる機能の設計

- 日付: 2026-09-30
- 土台にする設計: [PDF のページを参照で取り込む機能の設計](2026-09-28-pdf-page-strokes-design.md)
- 状態: 実装済み。UI での手動確認はまだ

## 目的

キャンバスを縮小したとき、教科書の章立てがページの並びから読み取れるようにする。
セクションごとに行を改め、入れ子の深さをページ 1 枚分の字下げで表す。
セクションは、しおりのある PDF ではしおりから、しおりのない PDF（スキャンした教科書など）では目次を見て手で書いたテキストから得る。

成功の条件は次のとおり。

- しおりのある PDF では、ダイアログを開いた時点でセクションの欄が埋まっており、そのまま取り込める
- しおりのない PDF では、目次に載っている印刷番号を字下げ付きで書き写すだけでセクションを指定できる
- セクションの欄が空なら、今の格子配置と同じ位置に並ぶ

## セクションのテキスト

1 行が 1 セクションを表す。
行頭の空白 2 つ、またはタブ 1 つごとに 1 段深くなる。
字下げの後ろに開始ページの番号を書き、その後ろに空白を挟んで見出しを書いてよい。
見出しは読み飛ばし、配置には使わない。
空行と空白だけの行は無視する。

```
1  第1章 ベクトル
  3  1.1 ベクトルの和
  9  1.2 内積
21 第2章 行列
  21 2.1 行列の積
```

番号は本に印刷されたページ番号として読む。
PDF のページ番号は「印刷番号 +（ずれ − 1）」で求める。
ずれは「本の 1 ページ目が PDF の何ページ目か」で、既定値は 1（印刷番号と PDF のページ番号が同じ）だ。

Max Depth は使う階層の数で、既定値は 2 だ。
深さを 0 から数え、深さが Max Depth 以上の行は配置に使わない。
使わない行のページは、配置の規則によって直前の使う行に入る。

### 検証

次のどれかに当たる行があれば、テキスト全体を無効とし、最初に当たった行の番号と理由を返す。
検証は Max Depth で除く行も含めた全部の行に対して行う。

1. 字下げの後ろが数字で始まらないか、数字の直後が空白でも行末でもない（`1.1 3` のように見出しを先に書いた行を拾うため）
2. 字下げの空白の数が 2 の倍数でない（タブは空白 2 つと数える）
3. 直前の行（空行を除く。以下同じ）より 2 段以上深い。最初の行は深さ 0 でなければならない
4. PDF のページ番号が直前の行より小さい
5. PDF のページ番号が 1 未満か、PDF のページ数を超える

しおりの順序が乱れている PDF では、しおりから埋めたテキストが 4 に当たる。
その場合は利用者が該当する行を直すか消す。

### しおりからの生成

しおりの各項目を、先頭から順に「字下げ + PDF のページ番号 + 空白 + 見出し」の 1 行にする。
見出しの中の改行とタブは空白に置き換える。
ずれは既定値の 1 のままなので、書いた番号はそのまま PDF のページ番号として読まれる。
深い階層の項目も省かずに書き、使う深さは Max Depth で選ぶ。

## 配置の規則

入力は、取り込むページの範囲、検証を通って Max Depth で絞ったセクションの一覧（PDF の開始ページと深さの組）、列数、間隔だ。

各ページは次の規則で 1 つのセクションに属する。

- 開始ページがそのページ以下であるセクションがなければ、前付けに属する
- あれば、そのうち開始ページが最も大きいものを見る。その開始ページがちょうどこのページなら、このページから始まるセクションのうち最初のもの（最も浅い親）に属する。そうでなければ、開始ページがこのページ以下であるセクションのうち最後のものに属する

例えば第 2 章と 2.1 がどちらも 21 ページから始まるとき、21 ページは第 2 章に、22 ページ以降は 2.1 に属する。
同じページを 2 回置くことはない。

セクションの開始ページは一覧の順に減らないので、1 つのセクションに属するページは連続する。
上から順に、前付け、各セクションの順で行を作る。
属するページが 0 枚のセクションと、属するページがすべてページ範囲の外にあるセクションは、行を作らない。
前付けは深さ 0 として扱う。

各行は `columns` 枚ごとに折り返す。
行の x は「深さ ×（列の幅 + 間隔）」で、折り返した後も同じ x から並べる。
列の幅は範囲内の全ページの最大幅、折り返した 1 段の高さはその段で最も高いページの高さに間隔を足したものにする（今の格子と同じ）。

セクションが 1 つもなければ全ページが前付けに属し、今の `grid_offsets` と同じ位置になる。
そのため `grid_offsets` はこの関数に置き換え、格子配置は特別な場合として扱う。

## しおりの読み取り

catalog の `/Outlines` から `/First` と `/Next` で兄弟を、各項目の `/First` で子をたどり、先行順に（見出し、PDF のページ番号、深さ）の一覧を返す。
再帰ではなく明示的なスタックでたどる。

行き先は、項目の `/Dest` と、`/A` のうち `/S` が `/GoTo` のものの `/D` から取る。
行き先の値は次のように解決する。

- 配列: 先頭の要素がページへの参照なので、全ページの `obj_id` からページ番号を引く表で引く
- 名前: catalog の `/Dests` の辞書（PDF 1.1 の形式）で引く
- 文字列: catalog の `/Names` の下の `/Dests` の name tree で引く。name tree は最初に一度全部たどって表にする
- 名前や文字列で引いた値が辞書なら、その `/D` を配列として読む

見出しは `/Title` の文字列を、先頭の BOM が UTF-16BE なら UTF-16BE として、UTF-8 なら UTF-8 として復号し、BOM がなければ Latin-1 として読む（PDFDocEncoding との違いは一部の記号だけなので、近似として扱う）。

行き先を解決できない項目（外部ファイルや URL への移動、存在しないページへの参照）は、その項目だけを飛ばす。
飛ばした項目の子は、飛ばした項目と同じ深さに繰り上げて続ける。

壊れた PDF に備えて、たどった項目と name tree の節の `obj_id` を覚えておき、2 回目に出会ったらそこでたどるのをやめる。
項目数は 10000 で打ち切る。
catalog や `/Outlines` が読めないなど、読み取り全体が失敗したときは、理由をログに出して空の一覧を返す。

`PdfSource` には、この一覧を返すメソッドを足す。
ダイアログは PDF を開く `gio::spawn_blocking` の中でこのメソッドを呼び、しおりからテキストを作る。

## ダイアログ

今の欄（最初のページ、最後のページ、列数、間隔）に、次の欄を足す。
UI の文字列は英語で、翻訳は付けない。

- `Book Page 1 Is PDF Page`: ずれ。1 からページ数まで、既定値は 1
- `Max Depth`: 1 から 16 まで、既定値は 2
- `Sections`: 複数行のテキスト欄。等幅の字体で、スクロールできる。初期値はしおりから作ったテキストで、しおりがなければ空

列数の上限は 64 からページ数に引き上げる（既定値は 8 とページ数の小さいほう）。
列数を大きくすると、各セクションを 1 行にまとめて横に伸ばす使い方ができる。

テキスト欄の下に、検証の結果を 1 行で表示する。
無効なら `Line 12: ...` の形で最初の問題を示し、`adw::AlertDialog::set_response_enabled` で Import を押せなくする。
有効なら使うセクションの数を示し、テキストが空なら格子で並べることを示す。
検証は、テキスト、ずれ、Max Depth のどれかが変わるたびに、エンジン側の解析関数を呼んで行う。

ダイアログを閉じると、テキストは残らない。
同じ PDF を取り込み直すときは、しおりから埋め直されるか、手で書き直す。

## テスト

`rnote-engine` の単体テスト:

- 解析: 空白とタブによる深さ、見出しの読み飛ばし、空行の無視、ずれの適用、Max Depth による除外、検証の 5 つの規則それぞれで正しい行番号が返ること
- 生成: しおりから作ったテキストを解析すると、元の一覧と同じ開始ページと深さになること
- 配置: 親と子が同じページから始まるとき、そのページが親の行に入ること。ページが 0 枚のセクションと範囲外のセクションが行を作らないこと。前付けが先頭に深さ 0 で並ぶこと。折り返しても x が保たれること。セクションが空なら、今の `grid_offsets` のテストと同じ位置になること
- しおりの読み取り: 下の 2 つの PDF で、見出し、ページ番号、深さが期待どおりになること

テスト用の PDF を 2 つ足す。

- `outline.pdf`: Typst で作る。入れ子の見出しを持ち、親と子が同じページから始まる箇所と、3 段目の見出しを含む
- `outline-edge.pdf`: PDF の文法で直接書いたテキストから、`make.sh` から呼ぶ `make-outline-edge.sh` が xref の位置を計算して作る。`/Dests` の辞書で引く名前の行き先、name tree で引く文字列の行き先、`/A` の `/GoTo`、UTF-16BE の見出し、解決できない行き先の項目とその子、自分自身を `/Next` に持つ循環する項目を含む

Typst が出すしおりの行き先が名前か配列かは実装のときに確かめ、`outline.pdf` で確かめられない形を `outline-edge.pdf` で補う。

最後に、しおりのある教科書とない教科書を 1 冊ずつ取り込み、縮小した表示で章立てが読めるかを確かめる（利用者が行う）。

## 退けた案

- セクションを PDF の隣のテキストファイル（`book.sections.txt`）に書く案: 一度書けば取り込み直しでも使える。しかし 2 台で PDF と一緒に持ち運ぶファイルが増える
- 開始ページを PDF の通し番号で書く案: 欄が 1 つ減る。しかし目次から書き写すたびに、各行にずれを足す計算を利用者がすることになる
- 親と子が同じページから始まるとき、そのページを両方の行に置く案: 章立てがそのまま見える。しかし同じページが 2 枚になり、片方への書き込みがもう片方に出ない
- 親と子が同じページから始まるとき、親の行を空けておく案: 区切りは明確だが、縮小したときに章の境目ごとに 1 ページ分の隙間ができる
- 字下げした行の右端を最上位の行にそろえる案: 全体が列数の幅に収まる。しかし列数を大きくしてセクションを 1 行ずつ横に伸ばす使い方と両立しない
- 見出しをキャンバスにテキストの要素として置く案: 縮小しても章の名前が読める。しかし要素が増え、文字の大きさと置き場所（行の間に隙間を空けるかどうか）を別に決める必要がある
- ページラベル（`/PageLabels`）から印刷番号を得る案: ずれの欄が要らなくなる場合がある。しかし付いていない PDF ではずれの欄が結局要る
